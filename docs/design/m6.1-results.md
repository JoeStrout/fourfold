# Fourfold: M6.1 Results — Markdown as a first-class format

*Status: 2026-11-05, at the end of M6.1 ([milestones.md](milestones.md)). Records what was built for Dynamic Markdown and Markdown as Markdown, the choices the milestone left open, and the known limits. The user-facing reference is [MARKDOWN.md](../user/MARKDOWN.md). No MS2 changes.*

## Summary

| Question | Outcome |
|---|---|
| Can a site be written entirely in Markdown, dynamic parts included? | **Yes.** `.md` pages and fragments have fields and includes, `about.md` pairs with `about.ms`, and `frag("row", list)` works for `.md` fragments. The `markdown-site` example has a visitor counter and a guestbook listing with no HTML. |
| Can a Markdown client read it? | **Yes.** Every Markdown page is also at `/x.md`, as `text/markdown; charset=utf-8; variant=GFM`: the same route, gate and code, its fields filled, with no layout. |
| Can a value change the structure of either output? | **No**, in every place a field can go (tested with a table of hostile values, each Markdown output parsed again and compared with the HTML output, and by fuzzing). The places where it could are compile errors. |
| Does visitor Markdown reach a Markdown client under the same rules as a browser? | **Yes.** `markdown(text)` is written back out as Markdown under its level's rules; parsed by a GFM client with raw HTML on, it has no HTML, and Limited Markdown has no headings or images (fuzzed). |
| Terminology | **Limited, Full and Dynamic Markdown** (2026-11-05). The `"comment"` profile is now `"limited"`, with no alias. |

## What was built

- **`template`:** `OutputFormat` (HTML or Markdown) in `RenderOptions`, with `markdownAlternate` for the `rel="alternate"` link. `CompiledTemplate` has a Markdown form (`markdownParts`) and a page title (`titleParts`) beside its HTML form; two new contexts, `MarkdownText` and `MarkdownBlock`. `render` writes either form; `renderMarkdownPage` (the layout or the built-in page, which moved here from the pipeline), `renderFragment`, `emptyRendering` and `pageTitle`. `resolveIncludes` splices both forms and refuses an HTML fragment in a Markdown template. `Html` carries a `MarkdownForm` (ready, deferred, or not made). New escapers: `escapeMarkdownText`, `markdownDestination`, `normalizeUrlPiece`. `kMarkdownContentType`.
- **`markdown`:** split into the renderer (`renderer.h`, `markdown.cpp`), Dynamic Markdown (`markdown_template.cpp`: `parseMarkdownTemplate`), and the writer (`writer.cpp`: `writeMarkdown`, `markdownValue`). `MarkdownProfile::Comment` is now `Limited`, and its wrapper class `markdown limited`.
- **`compiledapp`:** `RouteTable` has Markdown aliases (`addMarkdownAlias`, `findMarkdown`) and `findForUpdate` for the compiler; `markdownUrlFor`. `MarkdownPage` and `CompiledApp::markdownPages` are gone: Markdown pages are templates in `app.templates`. `describe` shows each Markdown URL, and a Markdown page's fields and title.
- **`compiler`:** `.md` fragments parsed as templates in the templates pass; `.md` pages in the Markdown pass (after routes, for link rewriting), with includes resolved and a `{{flash}}` field marking the route as using the session. The routes pass pairs `x.md` with `x.ms`'s `render` and adds each page's Markdown URL, checking it against every other route. The access pass keeps the aliases, and reads a Markdown page's `.ms` file's `access =`.
- **`script`:** `frag` uses `renderFragment` (an `.md` fragment's result is Markdown; its Markdown form is rendered when the run's output is Markdown), and an empty list gives an empty result of the fragment's kind. `markdown()` uses `markdownValue`, defaults to `"limited"`. `render` fills a paired `.md` page in the request's format. `req.format`. A fragment returned for `/x.md` is sent as Markdown if it is Markdown.
- **`pipeline`:** the route stage finds `/x.md` aliases (their one canonical form has no trailing slash); `setRenderFormat`; dispatch serves code-less Markdown pages in either format; a Render or Fragment outcome can carry Markdown's content type.
- **`devtools`:** the access report lists each `/x.md` URL, with its route's access.
- **Examples:** `markdown-site` gains `visits.md`/`.ms` (a counter) and `guestbook.md`/`.ms` with `frags/entry.md`; the guestbook's about page and the formatting page use the new terms.
- **Docs:** [MARKDOWN.md](../user/MARKDOWN.md) (new), the user guide's Markdown section, overview §4, architecture, README.

## Choices made here

- **Placeholders are Unicode noncharacters** (U+FDD0, hex digits as U+FDE0–U+FDEF, U+FDD1). md4c treats them as letters (not space or punctuation), so a field parses as a word would. A `.md` file in `code/` containing any of U+FDD0–U+FDEF is a compile error, so they can't clash.
- **The Markdown form is the source, split at its fields,** not the parse written back out. A page with no fields is sent exactly as written, as decided. The Markdown writer is used only for `markdown()` values.
- **Where each field landed comes from the renderer itself:** text, alt text, a title, a destination's start or a later part, a paragraph of its own, or code (where it's restored as written). A second parse with raw HTML on finds fields that a GFM client would read as part of raw HTML.
- **"Rendered late," as built:** a handle can't keep MiniScript values to render later, so `frag` of an `.md` fragment renders its HTML, and its Markdown only when the run's output is Markdown (in HTML runs it's marked as Markdown, with its form not made). `markdown(text)` keeps its text and writes the Markdown only if asked. Either way, the value is written in the format of the template it lands in.
- **More places fields can't go**, each because the Markdown output could otherwise mean something the HTML doesn't:
  - inside literal `[brackets]` that aren't a link (`[{{name}}]` could match a reference definition in the Markdown; escaped brackets are fine);
  - in a run of text with `://`, `www.` or an unescaped `@` (a client would link the bare address, with the value in its URL; md4c doesn't link it in the HTML, because the placeholder isn't an address character);
  - right after `<`, as in HTML templates;
  - inside raw HTML;
  - in a destination whose literal start breaks the URL rule (`javascript:{{x}}`).
- **Reference definitions** are found two ways: a field in a definition's label never lands anywhere, and one in a definition's destination lands in every link that uses it, or has no `](` before it on its line. So a field in an inline link whose destination or title starts on a later line is refused too (rare; put the link on one line).
- **Text values in the Markdown** also get trailing spaces as `&#32;` (two would make a hard line break), and a final `www` before a literal `.` written as an entity (`{{x}}.com` with `www` would make a web address).
- **A block must be a paragraph of its own**, with a blank line after as well as before: otherwise the next line continues the paragraph, and the field isn't alone. A field alone on its line may hold a string, which is then a paragraph.
- **Blank lines around blocks in the Markdown:** a block value or include gets a blank line before it unless one is there, and its last line is ended by the field's own line end.
- **The page title** is the first `#` heading's text with its values (plain text; the layout escapes it). Heading ids leave fields out, as decided.
- **The writer's escaping** is chosen for readability as well as safety: always `\ ` * _ [ ] < > & | ~ # @`; `-`, `+` and `=` first on a line; `.` or `)` after digits first on a line; `.` after `www`; `/` after `:`; spaces first on a line as `&#32;`. Code blocks are always fenced; links and images are always inline, with `<...>` around a destination with parentheses; reference links become inline; entities are kept as written.
- **Limited Markdown's image inside a link** is now its text, in the HTML as in the Markdown (before, the HTML had a link in a link, which isn't valid).
- **No CSRF cookie** on a Markdown response, since it has no forms; the security headers are the same.
- **`/x.md/`** redirects to `/x.md`, and `/x.md` for an HTML page is a 404.

## Known limits

- **An empty value** can leave a template's own markers unpaired in the Markdown (`**{{v}}**` becomes `****`), which a client then shows as text. Nothing of the value's gets through, since there is none.
- **Emphasis tight against a field mid-word** (`a*{{x}}*b`) pairs differently in the Markdown when the value starts or ends with punctuation: the client shows the asterisks, where the HTML had emphasis. The value stays text.
- **A fragment's link reference definitions** are global in the Markdown output of a page that includes it, so two fragments, or a fragment and its page, that define the same label resolve to the first one in the Markdown (in the HTML each is parsed alone).
- **A `|` in code in a table cell** is written as is, since md4c doesn't split a cell inside a code span; GFM clients do, so for them the cell splits.
- **Limited Markdown's empty heading** (`#`) renders as an empty paragraph, which the writer writes as nothing.
- **Footnotes** are still unsupported (M4).

## Tests

- `tests/markdown/markdown_template_test.cpp` (new): fields in both forms; a page with no fields sent exactly as written; code spans and blocks; titles; links and images; block fields with strings, `markdown()` values and null; HTML and rendered values refused in both outputs; includes in both forms, and HTML fragments refused; every placement error; error lines; the Markdown escapers; and **the exit criterion's escaping table**: 16 templates (text, emphasis, a paragraph of its own, lists, quotes, table cells, link text, URL parts, alt text, titles, glued to `.com`, a setext heading, lazy lines) × 37 hostile values (every ASCII punctuation character, line breaks, leading and trailing spaces, block starters, `|`, `javascript:` and malformed URLs, raw HTML, `www.`, bare URLs and emails, `[[`, `{{`, Unicode), each Markdown output parsed again and compared with the HTML output.
- `tests/markdown/writer_test.cpp` (new): readable output; reference links inlined; Limited Markdown's rules; escaping; 42 round trips in both profiles (written, parsed again, the same HTML; and writing again gives the same text); `markdownValue`.
- `tests/fuzz/fuzz_test.cpp`: **the writer**, on 11,000 mutated and random inputs in both profiles, parsed by md4c as a GFM client with raw HTML on: no HTML, safe URLs, and in Limited Markdown no headings or images; **mutated Markdown templates** (5,000), filled with a hostile value, checked in both outputs; and linear time for the writer and the template parser on adversarial inputs (one, a long run of fields with no spaces, found a quadratic case in the bare-address check, now fixed).
- `tests/compiler/routes_test.cpp`: Markdown pages with code, `{{flash}}`, aliases, title and fields in the description; placement and include errors with file and line; Markdown URLs colliding with other routes; every example compiles; golden files updated.
- `tests/script/script_host_test.cpp`: `.md` fragments with fields and lists, in both formats; `render` filling a Markdown page in each format with `req.format`; HTML fragments and `unsafeHTML` refused in a Markdown page; fragments returned for `/x.md`.
- `tests/engine/pipeline/engine_test.cpp`: a Markdown page at `/guide` and `/guide.md`, the alternate link, the content type, no layout, the trailing-slash redirect, and no `/book.md` for an HTML page.
- `tests/hosts/cli/app_server_test.cpp`: **the exit criterion**, the `markdown-site` example's counter and guestbook at `/x` and `/x.md`, end to end.
- `tests/hosts/cli/access_test.cpp`: **the exit criterion**, the clubhouse's members-only `/members/handbook.md` refused as `/members/handbook` is (and `/about.md` public), for every kind of visitor; the access report lists both.

All 21 suites pass with the `dev`, `ci` and `asan` presets. Every existing sample and fixture compiles unchanged: each `{{` in their Markdown was already in a code span, and none had `[[`.
