## What the exit test found

- **The CSP blocked every web build.** Unity compiles WebAssembly, which needs `'wasm-unsafe-eval'`; Unity 2019's `UnityLoader.js` (RoboReindeer, `demo`, `rrr`) also unpacks the `.unityweb` files in a `blob:` worker and runs the engine's JavaScript from a `blob:` URL. Added `config.headers.webAssembly` (off by default), and `"blob:"` as the one scheme `csp.script` accepts. Neither lets anything run that the page's own scripts didn't build. Neither framework needs `eval`: RoboReindeer's page calls are a `.jslib` plugin, and Mini Micro's one `eval` is `Application.ExternalEval`, unused at startup.
- **The link check called `href="wiki/"` broken** although `routes.ms` redirects it. It now accepts any URL a rule answers.
- **`deploy.sh` staged uploads in `/tmp`**, a 475 MB RAM disk on the VPS, which the 605 MB site overflowed. It stages in `/var/tmp` now.

- `code/static.ms` adds `unityweb`, `data`, `minidisk`, `grfon`, `gz`, `whl`, `dat` (text, as Apache's `AddType` had it) and `xml` (as RSS; `browserconfig.xml` gets that type too, which no browser minds), and a week's `maxAge` for the favicons. Release downloads keep their names when replaced, so they revalidate instead.
- `code/routes.ms`: the wiki (`/wiki/…` and `/w/…`), `/tryit/index.php`, the share links, and the favicon set.
- `private/config/app.ms`: `webAssembly`, `blob:`, and the CDNs the pages use (jsDelivr, cdnjs, jQuery, Bootstrap, Font Awesome, reCAPTCHA, and YouTube for a frame).
