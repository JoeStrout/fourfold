# Fourfold: M5.1 Results — Files in `data/`

*Status: 2026-10-26, at the end of M5.1, a mini-milestone between M5 and M6 ([milestones.md](milestones.md)). Records what was built for the `file` module and `RawData`, and the few choices the milestone left open. No MS2 changes.*

## Summary

| Question | Outcome |
|---|---|
| Can an app keep files other than JSON in `data/`? | **Yes.** A `file` module reads and writes whole files anywhere in `data/`, as text (UTF-8 lines) or bytes (`RawData`). |
| Can it leave `data/`? | **No.** Paths go through `RelPath` and `DataDir`: no leading `/`, no `..`, no dot-names (so no `data/.fourfold/`), no `\`, and symbolic links are never followed. Tests try each. |
| Do `file` and `data` agree on locks? | **Yes.** Locks are per file, keyed by path, and `data` now locks its value file (`votes` → `votes.json`). A test holds a `data.update` open while a `file.writeLines` of the same file waits, then lands after it. |
| Is binary data contained? | **Yes.** `RawData` buffers are capped at 16 MB each and 64 MB per request, and can't go into `session`, `data` or `json()`. |
| Is anything in `data/` served by URL? | **No**, and no route can be made to: the route table comes only from `code/pages/`. |

---

## What was built

- **`partition`:** `DataDir` gained `makeFolder`, `removeFolder` (empty folders only) and `info` (kind, size, time), with the same `openat`, no-link-following rules as its other operations.
- **`appdata`:** `DataFiles` gained whole-file operations (`readFile`, `writeFile`, `removeFile`, `makeFolder`, `info`, `children`), `checkPath`, and the text helpers `splitLines` and `joinLines`. Its size cap (16 MB) covers files as well as values and logs.
- **`script/modules/file.cpp`:** the module: `readLines`, `writeLines`, `loadRaw`, `saveRaw`, `exists`, `info`, `children`, `makedir`, `delete`, `name`, `parent`, `child`. Disk work runs on the worker pool with the VM parked, as for `data`; the helpers for that moved from `data.cpp` into `data_work.{h,cpp}`, shared by both modules.
- **`script/modules/raw_data.cpp`:** `RawData`, Fourfold's own. An instance is a map whose `__isa` is a frozen class map, with a `_handle` holding a `Value::NewHandle` to the bytes. Each handle is checked against the set of live buffers before use, so a `_handle` set by a script to anything else reads as an empty buffer. The API is command-line MiniScript's: `len` (and `len =`), `resize(bytes=32)`, `littleEndian`, `byte`/`setByte` through `double`/`setDouble`, `utf8`, `setUtf8`.
- **`markdown()`** takes a list of lines as well as a string.
- **The guestbook** example gained a `/news` page, kept as `data/news.md` and written on the first visit.

## Choices made here

- **A leading `/` is an error.** `"/x"` could have meant `data/x`, but an error is clearer for code ported from elsewhere, where `/` means the server's root.
- **Lock keys are lowercased paths.** On a case-insensitive file system (macOS's default), `Votes.json` and `votes.json` are one file, so they share a lock. On Linux, this only makes two different files wait for each other, rarely.
- **A total `RawData` budget per request: 64 MB.** The per-buffer cap alone would let a loop make any number of 16 MB buffers, outside MS2's heap and so outside anything R4's eventual memory limit will count. Each buffer holds a shared pointer to its run's budget, so one freed by the garbage collector after the run ends still gives its bytes back. Since garbage isn't collected the moment it's dropped, reaching the budget first runs a collection, and fails only if the bytes are still in use. A test makes ten 15 MB buffers in a row, dropping each, and stays within budget.
- **Out-of-range offsets are errors**, as in command-line MiniScript; integer setters wrap like its casts, but without C++'s undefined conversions (NaN stores 0).
- **`utf8` stops at a zero byte**, as command-line MiniScript's does, and shows any bytes that aren't valid UTF-8 as U+FFFD, since MiniScript strings are text. `file.readLines` is stricter: a file that isn't valid UTF-8, or contains a zero byte, is an error that points to `file.loadRaw`.
- **`file.info`'s `path` is relative to `data/`** (never the host path), and its `date` is in UTC, so it doesn't depend on the server's time zone.
- **`data.append` stays lock-free.** Rewriting or deleting a log with `file` while appends happen can lose an entry; the user guide says so, rather than every append paying for a lock.
- **Missing files read as `null`**, not an error (`readLines`, `loadRaw`, `info`), so the common "first time?" check is `if lines == null`.
- **Left out:** `file.move` and `file.copy`, along with `open`, `curdir` and `setdir` (decided before the milestone). They can come later if apps need them.

## Tests

- `tests/partition/data_dir_test.cpp`: folders and `info`; neither follows a link out of `data/`.
- `tests/appdata/data_files_test.cpp`: paths, shared lock keys, whole files, `file` and `data` on the same `.json` file, the size cap, line splitting.
- `tests/hosts/cli/file_test.cpp`, end to end through `fourfold dev`'s server:
  - escape attempts;
  - a binary round trip of every accessor, in both byte orders;
  - `RawData`'s limits and forged handles;
  - `RawData` refused by `json()`, `session` and `data`;
  - the write that waits for `data.update`;
  - a Markdown page in `data/`, changed without a redeploy.
- `tests/hosts/cli/app_server_test.cpp`: the guestbook's news page, and that `/news.md` is a 404.

All 18 suites pass with the `dev`, `ci` and `asan` presets.
